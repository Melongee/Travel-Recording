## 2. 已确定的方向

- 个人、单人、本机使用；仅做 Web 页面和本地 Java 服务，以 Windows + Chrome / Edge 为主要验收环境。
- Java、Spring Boot、MyBatis-Plus、SQLite；Java 21 为目标。后端依赖的确切版本需在阶段 1 按官方资料核对并实际构建验证。
- React、TypeScript、Vite、Leaflet；复用当前 Demo 的组件、样式和交互，不为采用另一套组件库重做界面。
- 原始照片保持原位置，只读访问；不自动上传、移动、重命名、覆盖或删除。
- 照片最多关联一个地点，可关联这个地点下的多个类别；变更地点时清理旧地点类别；缺失原图仍保留分类。
- 离线时基础中国地图与本地照片管理可用，前提是本机服务在运行；详细底图和新地点搜索需要联网。
- 不加入 Agent、账号、多用户、云同步、微服务、Redis 或复杂任务平台。
- 用户采用 AI 编码方式，不亲自写代码；开发对话负责实现、检查和维护文档，用户负责体验反馈和产品决策。

## 4. 首轮开发的交付边界

先完成这一条真实链路：

> 添加一个小型测试照片目录 → 手动扫描 → 浏览真实缩略图 → 创建一个地点和类别 → 将照片归类 → 重启服务后仍能找到原来的分类。

按下面的顺序逐步实现，每一步都留下可运行结果：

| 顺序 | 具体工作 | 可检查的结果 |
|---|---|---|
| 1 | 检查实际 Java/Node 工具链，核对后端依赖组合；建立本地 Git、忽略规则和简明 README | 固定构建入口；个人照片、数据库、缓存、日志、备份和密钥不进入 Git |
| 2 | 建立 `backend/`、Maven Wrapper、SQLite 和第一份迁移；从 Demo 提取 `frontend/` 并接上最小 API | 本机服务可启动，数据库可初始化；页面能区分加载失败和空图库 |
| 3 | 用户输入一个测试目录，执行单个扫描任务，保存照片索引、读取元数据并生成缩略图 | JPEG/PNG/WebP 样本可浏览；中文/空格路径可用；损坏图独立失败；再次扫描无重复记录 |
| 4 | 接入最小地点、类别、照片归类和筛选接口，复用现有地图及查看器 | 真实照片可归入一个地点/类别，省份和地点数量来自后端，查看器遵守筛选范围 |
| 5 | 重启验证、原图只读检查和一次前后端打包运行 | 分类不丢失；数据库、缓存与原图分开；JAR 能提供页面、接口与本地静态资源 |

首轮不要求实现多目录完整策略、在线地图、完整路径恢复或 50,000 张容量验收。基础备份与向空图库恢复、离线首次加载、图像边界样本、在线地图/搜索及坐标验证，仍需按技术方案补完阶段 1；首个闭环完成不能宣称阶段 1 或 MVP 全部完成。

后续仍按“阶段 1 验证完成 → 阶段 2 MVP → 阶段 3 完整 V1.0”推进。不要一次生成整份 PRD 的所有功能。

## 5. 接入真实数据时必须注意

- 暂保留 `/demo` 作为体验对照，正式代码进入 `frontend/`、`backend/`。逐步抽出地图、图库、查看器、表单及数据访问，不继续把全部业务堆在一个页面文件中。
- 正式数据经 API 保存到 SQLite；localStorage 只能用于适当的界面偏好，不作为正式分类数据的权威来源。请求失败要有反馈，不能只修改页面造成保存成功的假象。
- 图库、缩略图条与大图翻页共用查询条件、稳定排序和分页语义；不能混入其他类别，也不能一次拉取全库原图。接近已加载边缘时获取相邻数据。
- 地点和省份数量来自真实记录，分类后同步刷新；不要沿用 Demo 常量。缺失文件保留照片 ID 和分类，不因磁盘暂不可访问而批量删除记录。
- 数据库、缩略图和日志放在独立应用数据目录；不要生成到用户照片根目录内，也不要将缓存再次扫描成照片。
- 本机服务默认绑定回环地址，照片资源按已登记 ID 读取，不提供任意路径下载；具体保护沿用技术方案，不扩展为复杂账号平台。
- 新启动脚本保留清晰错误、实际访问地址和失败后可见提示；Windows `.cmd` 使用 CRLF，避免重现窗口闪退问题。

## 6. 开发前需要准备什么

**用户可准备一份小型试用照片目录。** 几十张照片即可，优先使用副本；最好含横图、竖图、JPEG/PNG/WebP 和中文/空格路径。不必把个人照片提交仓库或上传到对话；开始真实试用时提供本机目录路径即可。

没有现成测试目录也可以开始：开发对话可用有授权的本地素材和生成的测试图片建立独立样本。几万张个人图库不需要在首轮准备。

**由开发对话完成：** 检查并记录工具链、确定兼容依赖版本、初始化本地 Git、实现最小数据库迁移与接口、编写必要验证和启动说明。应用数据目录等可配置实现细节使用明确默认值，不要求用户提前编写设计文档。

**后续再处理：** 地图 Key 在接入在线功能时通过本机配置提供，不能写进公开仓库；暂缺 Key 不阻塞离线主流程开发。GitHub 仓库、开源许可证及公开演示在对外发布前确定，不作为本机首个闭环的前置条件。
