# 1. 产品概述

## 1.1 项目背景

用户在旅行过程中积累了大量照片，包括风景照片、人物照片及其他旅行记录。

目前照片分散存放于电脑上的多个文件夹中，文件夹层级、命名方式及照片组织方式并不统一，导致以下问题：

1. 难以按照实际旅行地点快速查找照片。
2. 同一次旅行的照片可能分散在不同的本地目录中。
3. 现有文件夹结构无法满足灵活的照片分类需求。
4. 用户希望在不改变原始照片存储方式的前提下，获得统一、直观的照片浏览体验。
5. 传统文件夹浏览缺少地理位置关联，无法通过旅行地图直观回顾曾经去过的地方。

因此，希望开发一款以中国地图为主要交互入口、通过浏览器访问的本地照片管理应用。

## 1.2 产品目标

产品通过读取电脑上的照片目录，为用户建立独立的照片管理体系。

用户可以：

- 指定多个本地照片根目录，统一管理其中的照片。
- 按中国省级行政区和具体旅游地点组织照片。
- 在地图上创建、定位和浏览旅行地点。
- 为不同地点创建任意名称的照片类别。
- 手动将照片批量归入旅游地点及自定义类别。
- 通过地图地点标记进入照片图库。
- 使用完整的照片查看器浏览照片。
- 查看照片在电脑中的原始路径，并打开所在文件夹。
- 在原始照片被移动后恢复路径关联，而不丢失已有分类。
- 备份和恢复手动整理的分类数据。

## 1.3 核心设计原则

**原则一：不改变原始照片。**

所有原始照片保留在电脑原有位置。产品不应因扫描、浏览、分类等操作自动移动、重命名、覆盖、编辑或删除原始文件。

**原则二：物理目录与逻辑分类分离。**

电脑上的照片目录结构和产品中的地点分类结构相互独立。

即使同一旅游地点的照片位于多个不同文件夹中，也可以在产品内统一展示。

**原则三：地图是主要浏览入口。**

用户能够通过中国地图、省级行政区、具体地点逐层浏览照片，而不是只能依赖传统文件夹结构。

**原则四：用户自主决定照片分类。**

旅游地点和照片类别由用户手动创建与维护，产品第一版不需要利用 AI 自动识别照片内容或推断照片所属地点。

**原则五：本地优先。**

照片、分类信息和地点关联信息在本地管理。基础中国地图、省级边界与已保存地点在断网时仍可展示；联网用于详细地图底图及新地点搜索。断网不能影响已有照片的浏览、分类和基础地图导航。

**原则六：个人使用，功能优先。**

第一版以个人日常整理和浏览照片为主要目标。实现应保持简单，不以企业级业务流程、多用户并发或高可用架构为建设目标；原始照片保护、分类数据保存及基本备份恢复仍为必要能力。

# 2. 目标用户与运行环境

## 2.1 目标用户

第一版主要面向个人用户，适用于拥有大量旅行照片、希望长期整理和回顾旅行经历的人群。

不考虑多人协作、公共相册分享、团队权限管理等功能。

## 2.2 运行平台

- 产品以本地部署的 Web 应用形式交付，由浏览器页面和本地服务组成，不交付 Windows 桌面应用或桌面安装器。
- 本地服务运行在能够读取原始照片目录的计算机上，用户启动服务后，通过浏览器访问本机地址。
- 提供清晰的启动、停止及访问说明，可提供便捷启动脚本；不能要求用户编写代码才能启动产品。
- 第一版以 Windows 本机运行服务、当前稳定版 Chrome / Edge 访问为主要验收环境。其他服务端系统及浏览器的兼容性在实际验证后另行说明。
- 浏览器负责页面交互，本地服务负责读取照片目录和保存管理数据；目录路径以本地服务所在计算机为准。
- 默认仅供本机单人使用，不要求公网部署、跨设备访问或云端照片托管。
- 不强制要求用户注册账号或登录。

## 2.3 网络要求

产品采用“本地服务与照片管理 + 离线基础地图 + 在线详细地图及地点搜索”的运行模式。

**联网状态：**

支持基础地图和详细底图展示、地点名称搜索、坐标匹配、地点创建、照片整理和照片浏览。

**离线状态：**

在本地服务正常运行、照片所在磁盘可访问的前提下，仍然支持：

- 中国基础轮廓与省级边界展示。
- 点击省级行政区放大、查看已保存地点标记，并从地点进入照片库。
- 已保存地点列表与本地地点查找。
- 照片浏览、已有地点与自定义类别管理、照片归类及本地目录扫描。
- 在基础地图上手动指定位置创建地点；离线时不提供在线地名匹配。

基础地图数据、界面资源与必要图标应随应用提供，不依赖曾经联网访问的浏览器缓存。第一版不要求详细道路、建筑、卫星影像等底图离线可用，也不要求离线搜索尚未保存的景点。

在线地图服务不可用时，保留基础地图并提示详细底图或在线搜索暂不可用；地点列表仍作为并行浏览入口。这里的“离线”指外部网络断开，不包含本地服务停止运行。

# 3. 产品信息结构

## 3.1 逻辑分类体系

产品采用以下分类层级：

```text
中国旅行地图
│
├── 青海省
│   ├── 青海湖
│   │   ├── 全部照片
│   │   ├── 风景
│   │   ├── 人像
│   │   └── 其他自定义类别
│   │
│   ├── 黑独山
│   │   ├── 全部照片
│   │   ├── A类
│   │   └── B类
│   │
│   └── 翡翠湖
│       └── 全部照片
│
├── 四川省
│   └── 用户创建的具体地点
│
└── 云南省
    └── 用户创建的具体地点
```

其中：

**省级行政区：** 由系统提供标准行政区划，包括省、自治区、直辖市及特别行政区，用户不需要手动创建行政区划。

**具体旅游地点：** 由用户自行创建，例如青海湖、黑独山、翡翠湖。

**自定义照片类别：** 由用户在具体旅游地点下创建，例如风景、人像、A 类、B 类等。不同地点可以拥有完全不同的类别体系。

**全部照片：** 不是独立的存储类别，而是该地点所有关联照片的统一浏览入口。

第一版以“省级行政区 → 具体地点 → 自定义类别”为基本分类结构，不要求无限层级嵌套。

## 3.2 照片关联规则

1. 每张照片最多只能关联一个具体旅游地点。
2. 每张照片可以同时关联所属地点下的多个自定义类别。
3. 照片允许不关联任何自定义类别。
4. 只要照片已经关联具体旅游地点，就视为已完成地点分类。
5. 尚未关联任何具体旅游地点的照片属于“未分类照片”。
6. 不同时间拍摄的同一地点照片统一管理，不强制区分旅行批次。
7. 修改照片所属地点时，原地点关联被替换；为避免类别错配，原地点下的类别关联应清除，并在操作前提示用户。
8. “全部照片”视图中，同一张照片只展示一次，即使它关联了多个自定义类别。

# 4. 功能需求

## 4.1 本地照片目录管理

**FR-001：添加多个照片根目录**

用户可以通过输入目录路径或页面内目录浏览选择，添加一个或多个本地照片根目录。所选目录必须是本地服务能够读取的目录；本机部署时即为用户电脑上的目录，不要求上传原始照片。

2026-10-23 用户反馈及实现：正常页面入口改为点击“选择文件夹”打开 Windows 原生文件夹选择窗口，回显绝对路径后确认添加，不再要求手输路径。取消选择不登记目录，重新选择时取消保留此前路径；确认添加仍复用原目录安全校验。本轮仍由用户手动扫描，启动自动扫描另行实现。

2026-10-23 移除目录补记：设置页允许移除误挂载目录，预览并确认索引删除影响。移除后删除该目录下不再被其他有效挂载目录覆盖的照片索引及地点/类别关联，包括已排除、缺失照片；全部、未分类、地点/类别相册及排除列表同步消失，统计和封面刷新。重叠目录仍覆盖的照片保留原 ID/归类/排除状态并调整所属根目录，停用或恢复后待确认的目录不视为有效覆盖。取消不修改，扫描中禁止移除，预览后索引变化需重新核对；原图、磁盘目录、地点和类别本身不删除。重新挂载只重新建立已删除索引，不自动找回旧分类。

例如：

```text
D:\旅行照片
E:\相机照片
F:\手机备份
```

产品将不同根目录的照片纳入同一个图库统一管理。

**FR-002：递归读取子目录**

添加根目录后，自动扫描其下所有层级的子文件夹，不要求用户逐个指定子文件夹。

**FR-003：启动自动扫描（用户已取消）**

每次启动本地服务时，自动检查所有已配置的照片根目录，识别新增或发生变化的照片。打开、刷新网页或增加浏览器标签页，不应重复创建同一轮扫描任务。

**FR-004：手动刷新**

提供手动扫描或刷新入口，用户可以随时检查根目录中的照片变化。

**FR-005：增量更新**

已经完成索引且没有变化的照片不应在每次启动时重复进行全部处理。

**FR-006：文件重复扫描规则**

同一个实际文件即使被多个相互包含的扫描目录覆盖，也只建立一条照片记录。

但不同物理路径下的照片，即使文件内容完全相同，也作为独立照片管理。

不要求提供照片内容查重功能。

**FR-007：照片格式**

第一版支持：

- JPG / JPEG
- PNG
- WebP

不要求支持 HEIC、HEIF、RAW 及视频文件。

不支持的文件类型应跳过，不得因此中断整个照片扫描过程。

**FR-008：扫描状态反馈**

用户可以查看扫描状态，包括扫描中、扫描完成、扫描失败，以及发现的新增照片数量。

扫描过程中应尽量允许用户继续浏览已经建立索引的照片。

## 4.2 地图管理与旅行地点创建

**FR-009：中国地图首页**

软件提供中国地图作为核心浏览页面。

基础地图及省级边界在离线状态下仍然可用；联网时可叠加详细地图底图。

鼠标位于地图区域时，滚轮直接缩放地图；地图外的滚轮仍用于页面滚动。全国初始视野在普通窗口和全屏下均可直接切换在线底图，不要求先手动放大。

地图按照中国省级行政区划组织旅行地点。

应能够直观区分已经创建旅行地点的省级行政区与尚未创建地点的区域。

全国视图不展示地点照片或照片缩略图，以保留省界与整体轮廓的可读性。有旅行地点的省份使用高亮与轻量足迹标签，例如“青海 2处”；数字表示该省已创建的旅行地点数。悬停时可查看该省的地点数和已归入这些地点的照片数量，点击标签与点击省份具有相同的导航效果。

足迹标签应保持紧凑，避免与相邻省名重叠；触屏环境不能依赖悬停才能进入省份。首页的地点列表和最近照片区仍可展示图片，上述限制针对全国地图内部。

**FR-010：分层地图浏览**

地图采用以下交互方式：

1. 用户进入中国地图。
2. 点击某个省级行政区，例如青海省。
3. 地图定位并放大至青海省。
4. 展示该省下已经创建的旅游地点标记，可使用地点照片封面缩略图、地点名称与照片数量；没有可用封面时使用普通点位。
5. 点击具体地点标记，例如青海湖。
6. 打开青海湖的照片图库。

应支持从地点图库返回省级地图，以及从省级地图返回中国地图。

**FR-011：创建具体旅游地点**

用户可以在指定省级行政区下创建旅游地点。

创建时至少需要确定：

- 地点名称。
- 所属省级行政区。
- 地理坐标。

**FR-012：地点搜索与坐标匹配**

用户输入地点名称后，软件自动在全国范围搜索匹配的地理位置，并展示候选结果，不要求预先选择省份或点击搜索按钮。输入至少 2 个字并停顿约 450 毫秒后请求，中文输入法组词期间不请求；新输入不能被旧请求的候选覆盖。

用户选择候选地点后，自动填写所属省份和坐标，地图定位到相应位置；候选显示名称、省份与地址以便区分同名地点。供应商结果缺少可识别的省份时提示手动选择，不能沿用其他候选的省份。仍允许手动选择省份和位置。

此功能需要联网。离线时应明确提示，并允许用户选择已有地点或在基础地图上手动标点。

**FR-013：手动指定或修正位置**

当搜索结果不准确，或用户希望创建非标准景点时，允许：

- 在地图上点击选择地点。
- 拖动地点标记以修正位置。
- 确认最终坐标并保存。

**FR-014：地点维护**

允许对已创建的旅游地点进行重命名、修改坐标及删除管理记录。

删除地点时不得删除任何原始照片；原本归属于该地点的照片应恢复为未分类状态，并在删除前明确提示影响。

**FR-015：地点列表**

除地图之外，产品还应提供地点列表，用于查找和访问已经创建的地点。

地点列表在离线时仍然可用。

## 4.3 自定义照片类别管理

**FR-016：创建类别**

每个旅游地点下允许创建任意名称的自定义类别。

不预设“风景”“人像”等强制类别。

**FR-017：类别独立管理**

不同旅游地点的类别互相独立。

例如青海湖可以使用“风景、人像”，黑独山则使用“A、B”，两者不需要保持一致。

**FR-018：编辑类别**

允许用户重命名和删除自定义类别。

删除类别时，只移除照片与该类别的关联，不删除照片文件，也不取消照片所属旅游地点。

**FR-019：多类别关联**

同一张照片可以同时加入同一地点下的多个类别。

例如：

```text
照片 IMG_001.jpg
所属地点：青海湖
所属类别：风景、人像
```

## 4.4 照片分类与批量操作

**FR-020：未分类照片区**

产品提供独立的“未分类照片”入口。

所有尚未关联具体旅游地点的照片都出现在该区域。

已经指定地点、但尚未设置任何自定义类别的照片，不属于未分类照片。

**FR-021：先选择照片再归类**

用户可以从全部照片或未分类照片中：

1. 选择一张或多张照片。
2. 点击批量归类。
3. 指定旅游地点。
4. 可选一个或多个该地点下的类别。
5. 确认后完成分类。

**FR-022：先选择地点再添加照片**

用户可以：

1. 通过地图或地点列表进入某个地点。
2. 点击添加照片。
3. 从已经扫描的本地图库中选择照片。
4. 批量添加到当前地点。
5. 根据需要选择自定义类别。

2026-10-23 实现补记：地点页及地点/类别空状态提供“添加照片”；候选来自全部或未分类的已扫描照片，过滤已排除照片，支持搜索、排序、分页与跨页保留选择。当前类别默认选中，保存前确认跨地点影响。同地点已有类别保留并追加所选类别，跨地点移入清除旧类别；不重复收录。取消不写入，失败保留选片，成功后刷新相关统计并留在当前地点。

**FR-023：批量分类能力**

允许一次对几十张至上百张照片执行相同的地点或类别关联操作。

**FR-024：分类调整**

用户可以随时：

- 修改照片所属旅游地点。
- 添加新的自定义类别。
- 移除已有自定义类别。
- 取消照片的地点关联。

取消地点关联后，照片重新进入未分类照片区。

这些操作只改变产品内的管理关系，不影响原始照片。

**FR-024A：批量排除不收录的照片（2026-10-23 用户补充）**

允许从现有图库批量选择不想收录的照片，确认后从全部、未分类及地点/类别相册隐藏，并同步统计与封面。重扫、重启、备份恢复后仍保持排除，不删除、移动或改写电脑原文件。保留按路径识别的排除记录及原有归类，在设置中提供已排除照片的查看和批量恢复入口；恢复后继续沿用原地点与类别（其管理记录仍存在时）。

## 4.5 照片图库与查看器

**FR-025：缩略图图库**

提供照片缩略图网格，用于展示全部照片、未分类照片或某个地点下的照片。

应支持滚动浏览大量图片。

**FR-026：地点默认展示全部照片**

用户点击青海湖时，默认展示青海湖下的全部照片，而不是强制先进入子类别。

即使某张照片没有任何自定义类别，也必须能够在青海湖的全部照片中看到。

**FR-027：按自定义类别筛选**

进入地点图库后，提供类别筛选入口。

例如：

```text
青海湖

[全部照片] [风景] [人像] [A类]
```

选择具体类别时，只展示关联该类别的照片。

**FR-028：大图查看**

点击缩略图后，进入大图查看模式。

**FR-029：照片查看器操作**

支持：

- 上一张、下一张切换。
- 放大与缩小。
- 照片区域支持滚轮缩放，围绕鼠标位置调整；放大超出可视区域后支持鼠标左键拖拽，位置限制在图片边缘以内，切换照片重置缩放与偏移（2026-10-23 用户补充）。
- 全屏查看。
- 退出全屏或返回图库。
- 底部横向缩略图条，支持滚动及点击任意缩略图切换大图。
- 当前照片的缩略图高亮；使用左右按钮或键盘方向键切换大图时，当前缩略图自动滚入可见范围。

查看器与缩略图条应延续打开照片时的浏览范围和排序。例如，从“青海湖 → 风景”的搜索结果中打开照片，只在这一结果内切换，不混入其他类别或地点的照片。从全部照片进入时则浏览全部照片的当前筛选结果。

缩略图条应为大图保留独立空间，不遮住图片主体；照片较多时仍可分批浏览这一范围内的全部照片。

**FR-030：照片信息面板**

支持查看照片基本信息，包括：

- 文件名称。
- 原始文件完整路径。
- 所属旅游地点。
- 已关联的自定义类别。
- 图像分辨率。
- 拍摄日期（若原始文件包含相关信息）。

**FR-031：打开原始文件位置**

在浏览器与本地服务运行于同一台 Windows 计算机、且服务运行于当前桌面用户会话的验收环境下，提供“打开所在文件夹”功能。由本地服务响应用户主动点击，打开照片原始目录，并尽可能定位到对应文件。

不能要求正常本机使用的用户必须复制路径后手动寻找。页面同时提供复制路径作为补充及失败回退；若运行环境不支持调用文件管理器，应明确提示原因。网页本身不直接打开任意本地文件路径；未来非本机部署时不承诺打开访问者电脑上的文件夹。

## 4.6 原始文件失效与路径恢复

**FR-032：文件失效识别**

当原始照片被移动、重命名、删除，或者所在磁盘暂时不可访问时，软件应能够识别文件路径失效。

**FR-033：保留管理记录**

文件失效时不得自动删除照片索引，也不得丢失已经建立的地点及类别关联。

失效照片应显示“文件不可用”状态。

**FR-034：单张重新定位**

2026-10-23 实现：失效查看器通过系统文件窗口选择新位置，预览路径和旧/新影像，确认后保留照片 ID、地点/类别、排除状态及排序。以大小/尺寸和旧缩略图核对影像，未存旧原图字节指纹；缺少旧缩略图时必须人工确认，不静默信任同名文件。预览/确认时核对目标内容 SHA-256，拒绝变化、已占用路径、符号链接和应用数据目录。未挂载路径仅授权该单张文件，不扫描父目录；取消或事务失败不改变索引。

允许用户手动找到照片的新位置，恢复原照片记录与实际文件之间的关联。

恢复成功后，原有分类信息应完整保留。

**FR-035：批量目录重新定位**

2026-10-23 实现：设置页通过系统窗口选新目录，优先按相对路径、再按文件名/大小查找并以尺寸/旧缩略图核对候选。显示明确匹配、歧义/待核对、未匹配及原路径仍可访问数量；只默认选择通过核对的单一候选。歧义需明确选定，无旧缩略图需人工确认；未匹配或跳过的索引及归类保留。确认前重新校验所选文件内容与索引状态，重复目标、已占用路径、文件变动或扫描中拒绝提交，SQL 失败整批回滚。确认后挂载新目录，完整恢复替换旧挂载，部分恢复保留旧挂载；后续手动扫描正常收录新目录中的其他照片。保留照片 ID、地点、类别、排除和排序，原图只读；没有预存旧原图字节指纹，不将候选核对声称为原图字节相等。

当整个照片目录被移动时，用户可以指定新的目录位置。

例如：

```text
旧目录：
D:\旅行照片

新目录：
E:\照片备份\旅行照片
```

软件应尝试批量匹配对应的照片文件。

恢复前建议展示匹配结果，包括可恢复、未匹配和存在歧义的文件数量，供用户确认。

不能将无法确定对应关系的照片强制匹配到错误文件。

**FR-036：原始文件保护**

路径恢复过程只调整产品保存的文件关联信息，不修改、复制或移动原始照片。

## 4.7 数据保存与备份

**FR-037：自动保存管理信息**

用户建立的旅行地点、地理坐标、自定义类别、照片归属关系和其他管理信息必须持久保存。

关闭或重启软件后，这些数据不能丢失。

**FR-038：手动导出备份**

软件提供手动导出功能。

备份至少应包含：

- 已添加的照片根目录配置。
- 已建立的照片索引及文件路径信息。
- 旅游地点及坐标。
- 自定义类别。
- 照片与地点、类别的关联关系。

备份文件不需要包含原始照片。

**FR-039：手动导入恢复**

用户可以选择之前导出的备份文件，恢复照片管理数据。

如果恢复后的原照片路径发生变化，应能够配合路径重新定位功能恢复关联。

第一版不要求自动定期备份，也不要求云端同步。

# 5. 页面与交互需求

第一版建议包含以下主要页面和功能区域。

| 页面或模块 | 主要内容 |
|---|---|
| 旅行地图首页 | 离线基础中国地图、省级区域导航、地点标记、地点创建入口；联网时显示详细底图 |
| 地点列表 | 按省级行政区查看已创建地点，支持离线访问 |
| 全部照片 | 展示所有已经扫描并建立索引的照片 |
| 未分类照片 | 展示没有关联任何旅游地点的照片 |
| 地点照片库 | 展示对应地点的全部照片，支持自定义类别筛选 |
| 照片查看器 | 大图、缩放、全屏、切换、照片信息及原文件定位 |
| 照片归类界面 | 多选照片、指定地点、设置多个自定义类别 |
| 地点管理界面 | 新增、编辑、删除地点，搜索及调整地图坐标 |
| 设置与数据管理 | 管理多个扫描目录、手动刷新、备份导出与恢复、文件路径恢复 |

## 5.1 推荐主界面布局

主界面建议采用：

**左侧导航区域：**

- 旅行地图。
- 全部照片。
- 未分类照片。
- 地点列表。
- 设置。

**中间主要内容区域：**

根据当前操作显示中国地图、省级地图、照片缩略图库或照片大图。

**辅助操作区域：**

根据页面需要提供地点创建、类别管理、批量归类、照片详情等操作。

实际布局可以由 UI 设计阶段优化，不强制限定所有页面必须使用相同的区域划分。

## 5.2 基本交互要求

- 常用操作入口应清晰、直观。
- 批量选择照片后，应该能够明确看到已选择的照片数量。
- 对于会解除大量分类关联的操作，应要求用户确认。
- 扫描和路径恢复等可能持续较久的任务，应有状态提示。
- 在线详细底图或搜索加载失败时，基础地图、已保存地点与图库仍应可用；基础地图资源异常时再使用地点列表回退。
- 软件不应因为单张照片损坏而停止整个图库的加载。

# 6. 关键用户使用流程

## 6.1 首次使用

1. 用户按说明启动本地 Web 服务，通过浏览器访问本机页面。
2. 添加一个或多个本地服务可访问的照片根目录。
3. 软件扫描目录及其子文件夹。
4. 显示已发现的照片。
5. 没有地点关联的照片进入未分类照片区。
6. 用户可以开始创建地点并整理照片。

## 6.2 创建旅行地点

1. 进入旅行地图。
2. 选择省级行政区，例如青海省。
3. 输入地点名称，例如“青海湖”。
4. 系统搜索匹配的地理位置。
5. 用户选择搜索结果或手动在地图上标点。
6. 必要时拖动标记修正坐标。
7. 保存地点。
8. 之后可以为该地点创建自定义照片类别。

## 6.3 整理历史照片

1. 打开未分类照片区。
2. 浏览照片缩略图。
3. 批量选中属于青海湖的照片。
4. 指定地点为青海湖。
5. 根据需要选择风景、人像等类别。
6. 确认分类。
7. 照片自动从未分类照片区移出。

## 6.4 通过地图回顾旅行

1. 打开软件，进入中国地图。
2. 点击青海省。
3. 地图放大，展示青海湖、黑独山、翡翠湖等标记。
4. 点击青海湖。
5. 展示青海湖所有照片。
6. 可以点击风景、人像等类别进行筛选。
7. 点击照片进入大图浏览。
8. 根据需要查看原始文件路径或打开所在文件夹。

## 6.5 原始照片目录移动

1. 用户在 Windows 中移动原有照片目录。
2. 软件扫描后识别旧文件路径失效。
3. 原照片管理记录及分类关系保留。
4. 用户进入路径恢复功能。
5. 指定新照片目录。
6. 预览照片匹配结果。
7. 确认恢复。
8. 对匹配成功的照片更新关联路径。
9. 重新通过地图和图库正常浏览。

## 6.6 离线使用

1. 用户在没有外部网络连接的情况下启动本地服务并打开浏览器页面。
2. 中国基础轮廓、省级边界与已保存地点正常显示；详细底图和在线搜索显示不可用提示。
3. 用户通过地图点击青海省、青海湖标记，或通过地点列表进入青海湖。
4. 正常浏览、筛选、分类本地照片和扫描本地目录。
5. 网络恢复后，可以继续加载详细底图并使用在线地点搜索。

# 7. 非功能需求

## 7.1 性能与容量

原定 **10,000～50,000 张照片** 保留为设计参考场景；用户已于 2026-10-23 取消这一规模的专项能力/容量测试，不再要求以该测试作为交付前置条件。当前已完成独立 5,000 张生成样本的核心验证，实际体验与数据安全仍需持续保障。

要求：

- 按个人实际图库使用体验优化基本流畅性；不承诺未经验证的大规模测量结果。
- 已建立索引的照片能够较快展示。
- 大量照片不应导致缩略图库长期卡顿或崩溃。
- 本地服务启动时的自动扫描不能长时间阻塞浏览器界面，网页应在扫描完成前即可访问已有图库。
- 重启软件后不需要重新整理已有照片。
- 浏览大图时，应尽可能保持图片清晰并提供流畅切换体验。

不设置人为的照片数量硬性上限。

具体启动时间、加载时间及扫描速度结合实际使用环境记录；不再安排 10,000～50,000 张专项测试。

## 7.2 数据安全

- 不得因照片分类操作修改原始文件。
- 不得自动删除用户照片。
- 不得因扫描目录暂时无法访问而清除分类数据。
- 数据恢复及路径更新不能错误覆盖其他照片的管理信息。
- 软件异常关闭后，应尽可能保证已经保存的分类成果不丢失。

## 7.3 隐私要求

- 原始照片保存在用户本地。
- 不要求将照片上传至云端。
- 地图与地点搜索可以使用在线服务。
- 软件应明确区分本地照片处理和在线地理信息查询。
- 不应在用户不知情的情况下向第三方上传原始照片文件。
- 本地照片接口与管理页面默认仅供本机访问，不应因启动服务而自动向局域网或公网开放。

## 7.4 易用性

- 主要界面以中文为主。
- 适合普通个人用户操作，不要求具备技术知识。
- 应具有明确的空状态、加载状态和错误提示。
- 对重要或可能造成数据关联变化的操作提供确认与反馈。

# 8. 第一版不包含的功能

以下功能不属于当前版本范围：

1. 利用 AI 自动判断照片属于风景、人像或其他类别。
2. 根据照片 GPS 或拍摄时间自动归入旅游地点。
3. 人脸识别、人物自动识别。
4. 重复照片内容检测、智能去重或自动合并。
5. 照片裁剪、调色、滤镜等编辑功能。
6. 自动移动、重命名或删除本地照片。
7. 视频文件管理。
8. HEIC、HEIF 及 RAW 格式支持。
9. 按不同旅行批次建立独立相册。
10. 多人协作、用户账号、公开分享、云端相册同步。
11. Windows 原生桌面应用、桌面安装器及移动端原生应用；其他服务端操作系统的正式兼容性承诺。
12. 详细道路、建筑、卫星影像等完整离线底图，以及尚未保存景点的离线地名搜索；基础中国地图不在此排除范围内。
13. 自动定期备份。
14. 任意深度的照片分类嵌套。
15. 任何 Agent、对话助手或其他大模型功能。

后续版本可以根据实际使用情况再决定是否扩展。

# 9. 第一版验收标准

| 编号 | 测试场景 | 预期结果 |
|---|---|---|
| AC-01 | 添加三个不同的照片根目录 | 三个目录及所有符合格式的子目录照片均可统一浏览 |

# 10. 默认设计约定

以下细节尚未经过逐项需求确认，为保证第一版可以形成完整、可开发的产品范围，暂采用建议性的默认规则，后续可以根据实际使用体验调整。

1. **照片排序：** 默认按照拍摄日期排序；缺少拍摄日期时可使用文件时间信息。
2. **类别层级：** 仅支持具体地点下的一级自定义类别。
3. **地点删除：** 删除地点管理记录时，所属照片转入未分类区，不删除原始文件。
4. **类别删除：** 仅解除该类别与照片之间的关联。
5. **修改照片地点：** 旧地点下的类别关联一并移除，操作前明确告知用户。
6. **移除扫描根目录：** 默认停止后续扫描，不直接删除已经建立的照片分类记录；需要清理索引时另行明确操作。
7. **缩略图：** 采用按需加载方式，避免在大型图库中一次显示过多图片。
8. **地图标记：** 全国使用省份高亮与地点数足迹标签，省内展示用户创建地点的照片封面或普通点位，不自动导入大量无关景点。
9. **在线服务异常：** 保留基础地图与已保存地点，提示详细底图或在线搜索不可用；地点列表保持可用。
10. **备份恢复：** 恢复前应提示对现有管理数据的影响，防止误覆盖。
11. **Web 部署边界：** 第一版默认本机部署；本地目录均指后端所在计算机的目录。外部网络断开不影响本地服务，服务停止时页面不能继续执行管理操作。

# 11. 最终产品交付要求

第一版产品应达到以下结果：

**交付物：**

一个可在本机启动、通过浏览器访问的完整 Web 应用，包含页面、本地服务、基础离线地图资源、启动与停止说明及管理数据备份恢复说明。第一版以 Windows 主机上的 Chrome / Edge 为主要验收环境，不提供桌面应用安装包。

**核心体验：**

用户添加多个本地照片目录后，可以在不改变原始文件结构的情况下，自主创建旅行地点与照片类别，通过中国地图浏览照片，并能长期保存和恢复整理成果。

**必须具备的能力：**

- 多目录照片读取与自动刷新。
- 离线基础中国地图与省级分层导航，联网时的详细地图展示。
- 地点搜索与手动坐标定位。
- 自定义类别与批量照片归类。
- 全部照片、未分类照片和地点图库。
- 完整照片查看器。
- 原始文件路径查看及文件夹定位。
- 文件失效状态与单张、批量路径恢复。
- 无外部网络时的基础地图及本地照片管理。
- 手动数据备份与恢复。
- 不设置人为照片数量硬性上限，按实际使用反馈优化图库体验；10,000～50,000 张专项能力测试已由用户取消。

**最终验收目标：**

用户能够长期将该软件作为个人旅行照片的主要整理和浏览入口，在不同旅游地点之间通过地图自由切换，同时保留电脑上既有的全部照片存储结构。
