# 地图服务与离线验证

更新：2026-10-23。已接入在线服务并优化全屏缩放和自动选点；基础省界仍为交互示意，本记录不代表正式地图内容验收通过。

## 本机配置

供应商为天地图。控制台：https://console.tianditu.gov.cn/ 。当前由 Java 后端访问官方服务，Key 应选择**服务端**应用类型，并具有相应地图/搜索服务权限。浏览器端 Key 实测被官方拒绝，返回 HTTP 403、301012「权限类型错误」。应用会给出对应提示，不通过伪装客户端绕过类型限制。

将 `config/application-local.properties.example` 复制为 `config/application-local.properties`，仅在后者填写 `app.geography.tianditu-key`。执行 `Stop.cmd` 后再 `Start.cmd`。配置文件被 Git 忽略，不进入数据库或导出 ZIP，接口只返回是否配置，不返回 Key。

`app.geography.offline=true` 将禁止地图外部请求。也支持环境变量 `TIANDITU_KEY`、`TRAVEL_OFFLINE`；本机属性文件可以覆盖默认环境变量配置。更换配置后需要重启服务并刷新已打开的页面。

## 接入与坐标约定

- 地名搜索使用 [官方搜索 V2](https://lbs.tianditu.gov.cn/server/search2.html)。表单输入至少 2 字并停顿约 450 毫秒后，以全国国标码 `156000000`、queryType=12 搜索，最多展示 10 个候选；不预先要求选择省份。点击结果自动匹配省份与坐标、居中标记，可再手动修改。接口保留按省份编码查询的兼容能力。
- 在线底图使用 [官方 WMTS](http://lbs.tianditu.gov.cn/server/MapService.html) 的 `vec_w` 和 `cva_w`，HTTPS、标准 XYZ 行列及墨卡托投影，缩放级别 1～18。
- 浏览器只访问本机 API，Java 仅请求固定官方域名；不提供任意 URL 代理。响应限制大小、连接超时、图片需为 256×256；在线失败保留本地基础地图。不会向天地图传输照片、照片路径或类别，只发送搜索关键词/省份或瓦片行列等请求参数。
- 内部手动位置为 WGS84。天地图候选保留 CGCS2000 原始经纬度、POI ID、供应商及 `geographic-approximation` 标识，以相同经纬度数值作旅行地图近似显示。这不是有参数的精密大地坐标转换，不承诺米级精度，也不混用 GCJ-02。更改手动坐标后记录为手动来源。
- 搜索来源写入现有 `places.coordinate_source`，本轮仍为数据库 V1，没有追加迁移。编辑名称而不改坐标时保留原来源。
- 基础资源仍为 Demo 的 Natural Earth 公共领域省界；34 个区域及足迹标签、地点封面交互继续复用。来源及 [公共领域条款](https://www.naturalearthdata.com/about/terms-of-use/) 可查，但这不能代替中国地图边界、海域、标注、审图号及适用授权等正式核验。在线图层显示天地图来源，基础交互轮廓也明确标识。

## 本轮验证结果

- 无 Key/强制离线的契约测试确认外部 Transport 调用次数为 0；正常搜索解析、来源保留、异常坐标过滤、瓦片范围校验及错误信息不泄漏 Key 均通过。
- 用用户在本机配置的服务端 Key，从最终 JAR 查询“青海湖 / 青海”：返回 10 个候选，首项 `99.6858, 36.92779`；底图与注记各一块实测 HTTP 200，均为有效 PNG。浏览器完成在线搜索、选点、显示底图及保存的点击检查，证据位于 `artifacts/tianditu-live-search.json`、`artifacts/tianditu-*.png` 和 `artifacts/ui/`。这些结果仅本机保留。
- 在线可用不表示所有地区或全部缩放级别均已人工抽查。点位数值及保存来源已检查；精密坐标精度和正式地图内容仍未验收。

## 离线验证：用户断网手测地图通过，首次加载全流程待补记

2026-10-22 用户反馈：“我自己断网手动测试了一下，离线地图可以正常使用。”据此将**断网时离线基础地图可用**记为用户手工验收通过。此次反馈未明确是否使用无历史缓存的新会话，也未单独报告离线照片浏览与分类，暂不扩大为 AC-13 所有条件均已验收。后续回归补齐这些条件。

代码和打包资源已包含页面、脚本、样式、图标及 GeoJSON；默认基础地图和本地图片走同源接口。无 Key/强制离线测试不会创建外部 HTTP 客户端。但静态资源审查及接口测试不能替代 AC-13 的首次加载体验。

本轮曾创建独立 Chrome profile，配置不可达的外部代理并保留 localhost 直连，准备验证无历史缓存的离线首次加载。Windows 自动化工具因无法可靠识别当前浏览器 URL 而停止，未继续向该浏览器发送输入，也未将该项记为通过；独立测试 Chrome 已关闭，用户常用浏览器未修改。其他本机页面的点击检查不能补作此项证据。

可按以下步骤手工验收：

1. 启动本机服务。断开外网连接，保持本机回环可用；关闭已有的 InPrivate/无痕窗口，再新开一个全新的私密会话。
2. 首次访问 `http://127.0.0.1:8080/`。确认没有依赖旧窗口、CDN、在线字体或已缓存地图才能出现的内容。
3. 查看全国足迹，进入青海查看地点封面，打开地点相册和真实缩略图；进入查看器翻页，并按当前类别/搜索范围切换。
4. 新增手动地点、类别并归类一张测试照片，刷新和重启后核对仍在；仅操作自己希望保留的测试数据。
5. 点击在线地图/搜索时应有失败提示，并可继续回到基础地图；恢复外网后重新验证在线功能。

剩余阶段 1 地图工作：在用户断网地图手测通过的基础上，补齐无缓存首次加载及离线照片浏览/分类记录，落实正式基础地图资源及显示要求，补充多个省份/缩放级别和有代表性的点位抽查。

## 第三轮补测（2026-10-22）

使用 `scripts/verify-geography.py` 在最终应用网关抽查天安门（北京）、外滩（上海）、青海湖（青海）。三个官方候选均落在相应离线省份几何内，原始坐标来源与保存值一致；z=5/9/13 的 `vec/cva` 共 18 块瓦片均可解码为 256×256。结果保存在 `artifacts/round3-geography.json`，仍不承诺精密坐标转换或全部边界内容通过。

三点还保存到独立验证库，在页面逐一进行基础图与在线图的显示对照；截图位于 `artifacts/ui/round3-{beijing,shanghai,qinghai}-{offline,online}.jpg`，标记和省份导航保持可用，未改动用户主图库地点。

另在强制离线的独立服务首次打开页面，完成地图→地点→类别→查看器，以及百张归类、新建类别、一张新增归类、刷新/真实重启后的保存检查。用户先前的物理断网地图手测继续计为通过；本轮未清理用户浏览器全部缓存或改动主机网络，所以严格的新 profile/物理断网组合仍未另行记录为通过。详见 [MVP 验收记录](MVP验收记录.md)。

正式资源核对：官方[标准地图入口](https://bzdt.ch.mnr.gov.cn/)本轮浏览器返回证书错误，未绕过；天地图公开行政区入口读取不稳定。可查的[天地图北京标准地图说明](https://beijing.tianditu.gov.cn/bzdt/)列出静态图格式和使用说明，不能直接当作与 Leaflet 经纬度一致的已核验省级 GeoJSON。现有资源继续保持原来源及交互示意标识，本轮未完成正式离线矢量资源替换。

## 第四轮地图交互回归（2026-10-23）

已捕获具体故障：大视窗或低缩放时越过经度 180°，Leaflet 1.9 的 `noWrap` 关闭横向环绕，却未单独阻止按可环绕 CRS 判定的越界列号。例如 z=2 仍请求 x=4、5，后端按 `0 <= x < 2^z` 正确返回 400，前端因此回退。证据 `artifacts/round4-low-tiles.json`、`round4-invalid-tile-proof.json`，并核对了本机 Leaflet `GridLayer._isValidTile` 源码。现为两层增加世界边界，经度 ±180°、墨卡托纬度约 ±85.05112878°，阻止越界请求，保持原默认视野和 0.25 级细分；没有放宽后端校验。最终版本在 2032×1117、2560×1440 下直接切换各 64/64 瓦片成功，切换前后 SVG 几何相同；滚轮缩小到 z=2 后 24/24 瓦片成功，全部行列合法。参考 [Leaflet GridLayer bounds 选项](https://leafletjs.com/reference.html#gridlayer-bounds)。鼠标在地图内时实测滚轮放大/缩小，页面滚动不变；地图外滚轮仍滚动页面。

原实现收到任一 `tileerror` 就立即卸载两层。现等待批次完成，失败则延迟 350 毫秒重试一次，持续失败才回退；视野变化或关闭图层会取消旧重试。临时本机代理的一次失败后，普通 1280×720 视窗 18/18 瓦片成功；2032×1117 下持续模拟失败共 72 次（首批及重试），页面正确回到基础图，地点列表仍在。收尾滚轮缩小时捕获上述越界请求，因此移除了最初尝试的整数缩放规避方案，最终采用边界约束。证据为 `artifacts/round4-ui-checks.json`、`round4-*-proxy.json` 与 `artifacts/ui/round4-*.jpg`。

全国真实查询“天安门”“外滩”“青海湖”“西安青龙寺”各返回 10 个候选，省份编码均可解析。全国同名结果可能来自不同省份，按供应商返回顺序展示名称、省份和地址，由用户选择；没有把“外滩”第一项强行视为上海。页面先选天安门自动填写北京，随后输入青海湖并键盘选中，自动改为青海。独立库保存并重启后，省份、坐标及原始来源完全相同。受控延迟旧“青海湖”请求、先返回新“天安门”请求后，候选保持天安门。无 Key/强制离线零外部调用及来源解析的后端回归继续通过；真实中文输入法组词过程未另行人工验收。
