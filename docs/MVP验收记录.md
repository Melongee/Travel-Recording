# MVP 日常操作与 5,000 张样本验收

日期：2026-10-22。范围：文件夹定位、地点删除、独立样本的约 5,000 张图库验收，以及离线工作流补测。未实现完整 V1.0，正式基础地图资源尚未替换。

**2026-10-23 最新调整：** 本地省界检验已完成，来源/结构可追溯但有具体覆盖与显示限制，见地图验证记录。用户取消新增物理断网及严格无缓存组合专项，不再安排或作为交付门槛；既有 5,000 张与离线操作证据保留。下文为当时执行结果。

## 实现

- 照片查看器的信息面板增加“打开所在文件夹”。同源 POST `/api/photos/{id}/reveal` 使用 CSRF；只接受照片 ID，后端重新检查已登记目录、原图实际路径、链接及恢复后的访问确认。未知 ID、失效原图或未确认目录均不会启动桌面操作。
- 本机 Windows 会话调用资源管理器并选中原文件。使用固定 PowerShell 程序和固定脚本，路径通过子进程环境变量作为数据传递，保留 Explorer 所需引号；不把文件名拼接为脚本。检查 Session 0，限定等待时间，异常时页面提供复制路径回退。`TRAVEL_DESKTOP=false` 或 `app.desktop.enabled=false` 可禁用桌面操作。
- 地点详情和列表增加删除入口；确认前显示照片与类别数量，取消不改变数据。确认删除后照片返回未分类，类别及归属清除，照片索引与原文件保留。后端事务沿用现有外键；重复删除不存在地点返回 404。
- 维持现有全国足迹、省内封面、筛选与查看器缩略图条。主图库不导入生成样本、不删除用户地点；数据库仍为 V1，没有人为增加无业务用途的迁移。

## 生成样本及复现

生成器：`scripts/create-mvp-samples.py`（Python 3.10+、Pillow）。运行后输出一个新的 `test-data/mvp-5000-时间戳` 目录，含生成标记和 SHA-256/文件时间清单。

- 5,000 张有效 JPEG/PNG/WebP，另有 1 张损坏 JPG 和不支持的 TXT。
- 三个登记目录，其中一个是另一个的子目录，重叠覆盖 1,200 张。
- 主要为 800×600 和 480×720，混有 24MP 图片、透明 PNG 与 EXIF 旋转；同内容不同路径的两个文件保留独立索引。
- 特殊文件名为 `定位 中文 空格, & 原图.jpg`。用户个人照片不参与移动、删除或桌面定位测试。

完整 JAR 验收脚本：

```powershell
python scripts/create-mvp-samples.py
python scripts/verify-mvp.py --fixtures "上一步输出的完整样本目录" --java ".tools/jdk-21.0.12.1+1/bin/java.exe"
```

运行前构建 JAR。脚本默认使用 8095/8096、两个新数据目录，强制应用离线，不导入本机 Key 配置文件；只允许项目 `test-data` 下带生成标记的目录。端口已占用时停止验证，结束后自动停止进程。开发时可加 `--keep-source` 保留源验证服务用于页面检查；保留时需用 `Stop.cmd -DataDir "对应 source 数据目录"` 停止。

## 页面与离线补测

使用此前未在本轮浏览器打开的 8095 源验证服务，启动参数强制离线。首次打开页面，实际点击全国足迹→青海→地点封面→类别→搜索→查看器；缩略图和大图来自本机。页面一次全选 100 张并归入两个类别，两个类别各 100。

另外从页面创建“离线手工验证”类别，并将一张照片归入该类；刷新和真实重启后仍显示 1 张。地点删除先取消再确认，页面显示 3 张照片、2 个类别的影响；确认后总数 5,001 不变，未分类从 4,898 增至 4,901。证据在 `artifacts/ui/round3-offline-classification.jpg`、`round3-delete-preview.jpg`、`round3-place-deleted.jpg`。

用户先前已物理断网确认基础地图可用，本轮补测覆盖应用强制离线的浏览和写入。浏览器工具没有清空整个用户浏览器历史缓存，也没有再次改变主机网络设置，因此不把本轮写成“全新浏览器 profile + 主机物理断网”的组合验收。

资源管理器实测过程中发现含逗号路径未被选中，修正为固定脚本的参数保真传递，并处理初始化进度输出影响成功判断的问题；最终检查窗口实际选中上述生成原图。截图 `artifacts/ui/round3-explorer-selected.png` 与查看器截图只本机保存。
