## 2. 实际实现

- SQLite V1 迁移建立根目录、照片、地点、类别及照片类别表；UUID ID、规范化路径唯一约束、外键、类别归属触发器和查询索引。
- 每连接外键、5 秒 busy timeout、WAL、单连接池。图片解码与目录遍历在数据库事务外进行；批量归类为短事务。
- 添加可读本机目录后手动扫描，递归支持 JPEG/PNG/WebP；同一时间一个扫描任务。默认不跟随符号链接/目录联接，拒绝与应用数据目录互相包含的照片根目录。
- 以实际规范化路径去重；不同路径的相同内容保留独立照片。大小与修改时间未变化时复用缓存；损坏图片记录独立失败。
- 完整扫描成功才进行缺失差集判断。目录不可访问或遍历不完整时不批量判定缺失；不删除索引及分类。
- 480 像素 PNG 缩略图、按需 1920 像素 PNG 预览、EXIF 1～8 方向变换、透明通道、可读取的 EXIF 拍摄日期。拍摄时区未知时不伪造 UTC；缺少拍摄日期时明确用文件时间排序。
- 单线程解码，单图超过一亿像素时记录错误并继续其他图片。这是当前保护阈值，尚未验证各种超大相机照片。
- 地点创建/编辑、地点内类别创建/改名/删除、照片批量归类、单地点多类别、取消地点、跨地点清理旧类别。删除地点的 API 保留照片；地点删除 UI 未纳入本轮。
- 前端提取地图、图库、查看器、表单和 API 层，接入 TanStack Query 和 HashRouter；正式数据不使用 localStorage，也不导入 Demo 状态。
- 全国足迹、省内地点封面和类别数量来自后端；图库、查看器和底部缩略图条使用同一查询、稳定排序与分页。默认每页 100，最大 200；全选只选当前已加载的最后一页，按钮明确“当前页”。
- 加载失败、保存失败、空图库、损坏/缺失图有明确提示。保存后由后端刷新，不做虚假的本地保存成功。
- 默认绑定 `127.0.0.1`，页面/API 同源，限制 Host/Origin、跨站请求和 CSRF。图片只按已登记照片 ID 读取，并复查目录范围和链接，不提供任意路径下载接口。

地图继续使用 Demo 的 Natural Earth 公共领域资源，34 个交互区域、WGS84；地点存 WGS84/manual。已复核[官方公共领域条款](https://www.naturalearthdata.com/about/terms-of-use/)，不等于正式地图内容已核验，页面保留“交互示意”标识。正式前端只打包地图，不包含 12 张 Demo 示例照片。

## 4. 最小 API

| 接口 | 内容 |
|---|---|
| `GET /api/session` | 返回本机会话 CSRF token 与 headerName，变更请求携带该头和会话 cookie |
| `GET /api/overview` | 总数、未分类数、地点数量/封面、类别数量、目录与数据位置 |
| `GET/POST /api/roots` | 列出/添加根目录；JSON `{path}`，已存在的规范化目录直接返回原记录 |
| `POST /api/scans`、`GET /api/scans/current` | 启动/查询单任务扫描；返回发现、新增、更新、未变化、失败、缺失及有限错误清单 |
| `GET /api/photos` | `placeId`、`categoryId`、`unclassified`、`q`、`sort`、`page`（从 0）、`size`；返回 `{items,total,page,size}` |
| `GET /api/photos/{id}` | 完整路径、真实尺寸、拍摄时间/排序时间、地点、类别、可用状态、资源地址 |
| `GET /api/photos/{id}/thumbnail`、`/preview`、`/original` | 缩略图、预览、原图流；原文件失效时明确失败 |
| `POST /api/photos/classify` | `{photoIds,placeId,categoryIds}`；placeId 可 null，类别必须属于该地点，先检查整批再事务提交 |
| `GET/POST /api/places`、`PATCH/DELETE /api/places/{id}` | 地点管理；坐标需在有效范围且省份/编码一致，坐标体系固定为 WGS84/manual |
| `GET/POST /api/categories`、`PATCH/DELETE /api/categories/{id}` | 地点内类别管理；同地点名称唯一 |

排序为拍摄日期/文件时间升降序或文件名，均追加 ID 次序避免同名同日期分页不稳定。类别筛选使用 EXISTS，同一照片多类别不会重复。

## 7. 第二轮实施：备份恢复与在线地图

### 7.1 实际交付

1. **一致性备份。** 使用 SQLite `VACUUM INTO` 生成事务一致的快照，包含 WAL 已提交内容；不是直接复制在线主文件。[SQLite 官方说明](https://www.sqlite.org/lang_vacuum.html)。导出 ZIP 只含 `manifest.json`、`library.db`，记录格式/应用/数据库版本、UTC 时间、SHA-256 和目录/照片/地点/类别/关联数量；下载与服务器 `backups/` 各留一份。
2. **先校验再恢复。** 256 MiB 上传限制，解压后的数据库最大 512 MiB、清单 64 KiB；只接受两个指定条目，拒绝其他路径、重复项、不完整或损坏文件。临时库以只读、`trusted_schema=OFF` 校验结构、迁移版本/校验值、完整性、外键、数量、UUID、规范路径和跨地点类别关联，不执行备份附带脚本。
3. **空图库恢复。** 目录、照片、地点、类别或关联任一非空即拒绝恢复。预览令牌有效 1 小时，确认后再次校验。API 与扫描协调锁防止恢复时仍有数据库访问，关闭连接池后切换已校验的数据库，再重新打开。切换前保存一致快照，运行时切换/校验失败尝试回退；本轮没有模拟突然断电的恢复保证。
4. **导入路径不自动获得访问权。** 恢复目录全部禁用并标记 `needs_confirmation`；索引、地点和类别立即可查看，原图/缓存读取都要求先确认该目录。点击确认后按只读扫描重建缩略图；不存在的照片保留分类。未支持路径改名或整体迁移。
5. **在线地图与搜索。** 固定官方 HTTPS 地址代理 WMTS `vec_w/cva_w` 和地名搜索 V2；默认基础地图，用户点击才联网。服务端 Key 只在本机配置中，浏览器、数据库备份和 Git 均不包含它；无 Key、强制离线、断网或服务错误仍可使用基础地图和手动选点。搜索候选携带 CGCS2000 原始坐标及来源，内部作 WGS84 近似显示；选中点居中、置于封面上层，可再手动调整。详见 [地图服务与离线验证](地图服务与离线验证.md)。
6. **启动保护。** `Start.cmd` 先检查端口及健康接口，同端口/数据目录的本应用已运行时直接返回 `Already running`；不同服务占用时明确提示。每个数据目录有进程文件锁，防止两份服务同时操作同一个库。启动脚本加载 `config/application-local.properties`，仅 Java 在线请求沿用系统代理设置，不修改系统网络配置。

SQLite 仍为 V1，本轮未添加新表或迁移。`coordinate_source` 可保存搜索来源 JSON；保留手动来源和既有地点数据。
